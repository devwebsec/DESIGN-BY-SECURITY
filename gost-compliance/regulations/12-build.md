# 5.12 Secure Build — implementation regulation

> This document is an implementation overlay for the supplied ГОСТ Р 56939-2024 requirements. It is not a certification or legal compliance determination.

## 1. Goal — 5.12.1.1

The secure build process is intended to prevent introduction of defects caused by unsafe code transformations and to preserve traceability from source revision to resulting artifact.

## 2. Required build regulation — 5.12.2.1

The build process records:

- source revision and repository state;
- dependency and lockfile inputs;
- build system and runner;
- toolchain versions;
- build commands and configuration;
- transformation steps that can modify source or generated code;
- resulting artifact identifiers and digests;
- SBOM and provenance;
- signing state for release artifacts.

## 3. Build system and environment — 5.12.2.2

For each release/build record the framework fixes information about the build system and computing environment:

- CI system and workflow;
- runner image and architecture;
- operating-system version;
- compiler/interpreter/runtime/tool versions;
- container image digests when containers are used;
- relevant environment/configuration inputs.

The reference repository uses GitHub Actions and records the runner/workflow as part of the security design contract; production implementations must replace placeholders with exact observed versions.

## 4. Transformation control

Unsafe or unrecorded transformations are prohibited from being silently introduced into a release build. A transformation that changes executable semantics must be identifiable, reproducible and covered by validation evidence.

## 5. Reproducibility

A build is considered traceable when another authorized execution can identify the same source revision, dependency inputs, toolchain, commands and artifact digest. Full byte-for-byte reproducibility is a project-specific target; lack of it must not be hidden as an UNKNOWN or PASS.

## 6. Release evidence

Primary artifact: `gost-compliance/artifacts/secure-build.yml`.

Build-tool inventory: `gost-compliance/artifacts/build-tools.yml`.

Evidence package: generated by `gost-compliance/pipeline/evidence-package.sh` and protected by SHA-256 checksums.
